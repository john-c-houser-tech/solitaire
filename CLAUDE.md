# Quiet Solitaire

A single-page solitaire game. All code (HTML, CSS, JS, SVG card art) lives in one file.

## Files

- `solitaire.html` — the source. A page body with no `<!doctype>`/`<head>`. It is also what gets published as the claude.ai artifact, so it must stay self-contained.
- `index.html` — generated by `./build.sh` (wraps the body in a full document). Gitignored; never edit it by hand.
- `build.sh` — runs `npm run lint`, then writes `index.html`. Fails if lint fails.
- `githooks/` — tracked git hooks, enabled by `npm install`.
- `LICENSE` (MIT) covers the code and art; `OFL.txt` holds the notices for the fonts embedded in `FONT_CSS`. If you add or re-cut a font in `FONT_CSS`, keep name IDs 0, 13 and 14 (copyright and OFL) in the subset so the artifact copy stays compliant, and add its copyright line to `OFL.txt` and the comment above `FONT_CSS`. Court names use only the Uncial Antiqua subset's glyphs; for new letters, re-cut it from the full font with `pyftsubset --text=... --flavor=woff2 --name-IDs=0,1,2,3,4,5,6,13,14`.

## Commands

- `npm install` — once, for the dev-only ESLint dependencies. It also points git at `githooks/`, whose `post-commit` hook reminds you to republish the artifact when `solitaire.html` changes.
- `npm run lint` — lint the inline script in `solitaire.html`.
- `./build.sh` — lint and build.

## JavaScript conventions

Enforced by `eslint.config.js` (ESLint recommended plus a few style rules). `npm run lint` must pass.

- Everything sits inside one `(() => { 'use strict'; ... })();` wrapper. No modules, no globals, no build step, no runtime dependencies.
- Modern browser JS: `const` by default, `let` only when reassigned, never `var`. Arrow functions, template literals, destructuring.
- Single quotes, semicolons, 2-space indentation.
- Use `===`. `== null` is allowed for null/undefined checks.
- Compact style is intentional: short helpers and several related statements on one line are fine. Don't reformat existing code or run Prettier over it.
- Naming: `UPPER_SNAKE` for constant tables (`SUIT_NAME`, `PIPS`), `camelCase` for everything else.
- Sections are marked with `/* ================= name ================= */` banners (basics, decks, games, engine). Add code to the matching section.
- Comments are sparse. They explain why or describe non-obvious art and geometry, not what a line does.
- Persist settings only through the `store` helper (`qsol.`-prefixed `localStorage` keys, wrapped in try/catch). Empty `catch {}` is allowed there.
- Randomness for shuffles comes from `crypto.getRandomValues`, not `Math.random`.

## Page conventions

- Colors and fonts are CSS custom properties. Use the existing tokens instead of hard-coded values.
- Card faces are SVG in a 100×140 viewBox. Reuse shared `<symbol>`s and filters instead of duplicating art.
- Keep keyboard play, `aria-*` labels and `prefers-reduced-motion` handling working when changing UI or animation.
- External resources: Google Fonts only. Inline everything else.

## Git

`main` is John's: never commit or push to it, and never force-push. `dev` is the integration branch.

1. Before any new work: `git checkout dev && git pull --ff-only`.
2. Branch from dev: `git checkout -b <feature>`. Check `git branch --show-current` before every commit.
3. Commit there, push the branch, and open a PR into dev: `gh pr create --base dev`.
4. Request a Copilot review (`gh pr edit <n> --add-reviewer @copilot`) and address its comments with follow-up commits.
5. John merges to main. Wait for him.
